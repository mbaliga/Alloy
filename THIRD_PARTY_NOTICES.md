# Third-party notices

Alloy includes an optional native engine tree assembled from the
OrcaSlicer-Mobile/OrcaSlicer/PrusaSlicer family, with the integrated source
licensed under GNU AGPL-3.0. The copied upstream license text is at
`third_party/licenses/SLICEBEAM_AGPL-3.0.txt`; the root `LICENSE` is included
for distribution clarity.

Native source location:

`app/src/main/jni/`

Source provenance:

`utkabobr/SliceBeam@12b370ce305acc2caa59b7e4e78e04069db2f7e3`

The current Android slicer source is additionally pinned to:

`CodeMasterCody3D/OrcaSlicer-Mobile@d996a9cadb65b354997f2d5d8734b46bb9ea4efd`

That upstream project is explicitly experimental/alpha. Alloy uses its
Android-compatible `libslic3r` source, including the Arachne and
`TreeSupport3D` implementation, through Alloy's bounded Java/JNI and artifact
safety gates. This is not evidence of Bambu Studio `tree(auto)` parity; the
Bambu-specific support gate remains closed until its separate implementation
is ported and validated.

The organic-support path also contains an isolated, bounded adaptation of the
lightning-infill grounding pass from Bambu Studio `v02.08.02.61`
(`926a7192574bcb9b3a732e1ec59a46d79cb45466`). It remains behind Alloy's
support-parity gate and is not presented as Bambu Studio parity. The source
audit and transitive dependency inventory are generated by
`ci/audit_bambu_treesupport3d.py`.

The native tree contains additional third-party components with their own
notices, including CGAL and OpenVDB. Their in-tree license files remain next
to the corresponding sources. Before releasing a native-enabled APK, the
release process must generate a complete component inventory and provide the
corresponding source/offer required by the applicable licenses.

The native arithmetic dependency build uses:

- GNU MP (GMP) 6.2.1, under the GNU LGPL v3 or later, from the pinned official
  archive in `ci/build_gmp_mpfr_android.sh`;
- GNU MPFR 4.2.2, under the GNU LGPL v3 or later, from the pinned official
  archive in `ci/build_gmp_mpfr_android.sh`.

The archive URLs, SHA-256 values, Android cross-build parameters and generated
library metadata are recorded in `docs/NATIVE_DEPENDENCIES.md` and by the
source-build workflow. A native-enabled distribution must ship the applicable
GMP/MPFR license texts and corresponding source offer alongside the complete
SliceBeam and Orca/Prusa-derived source offers.

Alloy will not bundle Bambu's proprietary networking plugin or cloud client.

## Bouncy Castle

The Android FTPS transport uses Bouncy Castle Java 1.85/1.85.2
(`bcprov-jdk18on` and `bctls-jdk18on`) under the Bouncy Castle License. The
dependency coordinates and versions are pinned in `app/build.gradle`; the license text is available at
https://www.bouncycastle.org/licence.html. BCJSSE is used because its public
`BCSSLSocket.setBCSessionToResume` API lets Alloy enforce Bambu's required
control/data TLS session reuse.
