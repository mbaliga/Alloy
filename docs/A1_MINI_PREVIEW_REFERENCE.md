# A1 mini preview reference

Date: 2026-09-06

The user-supplied `3D Rendering Style Identification.zip` was reviewed as a
visual and interaction reference. The Android product keeps the Alloy
viewport as its runtime surface. A debug-only asset generated by
`tools/import_a1_preview_reference.py` now lets visual-review builds show the
supplied machine mesh in Machine view; it is intentionally absent from the
release source set until redistribution rights are recorded.

The importer accepts both forms of the handoff asset. The original 3MF can be
regenerated directly, without the ZIP's browser preview or third-party Python
packages:

```text
python3 tools/import_a1_preview_reference.py \
  "/path/to/Bambu Lab A1 Mini v5 3mf.3mf" \
  app/src/debug/assets/visuals/a1-mini-reference.mesh
```

The supplied 3MF currently regenerates as 16,054 triangles and 10,006 compact
vertices, matching the intended A1 Mini body study. It is still a local/debug
presentation asset, not a printable model or production collision envelope.

## Interaction direction

- Keep the solid model and toolpath preview as two views of the same plate.
- Make layer scrubbing cheap by keeping toolpath buffers in layer order and
  changing the visible draw range rather than clipping or reallocating.
- Show three distinct geometry states: printable, outside the build volume,
  and machine-clearance collision. Grey should indicate out-of-bounds; amber
  should indicate a collision hazard.
- Preserve the physical distinction between the black PEI plate and the
  surrounding workspace in both light and dark themes.
- Let the runway grid remain in plate-local coordinates, cross the physical
  sheet edge, and dissolve into the stage; the grid is an art-direction cue,
  not a second solid surface or a printable bed boundary. The native GLES
  study now keeps that grid in a separate line buffer so plate geometry and
  grid treatment cannot drift into one another.
- Keep the physical plate visually legible with bounded procedural grain and
  use small, Alloy-authored can/ball/key props as scale references in the
  standalone study; both are presentation-only.
- Keep an object-first Hero view separate from the technical plate view: the
  Android build now uses a light Alloy-owned studio plinth, contact shadow,
  and authored showcase hardware for the supplied product-study direction.
- In debug visual-review builds, Machine view may use the supplied 16,054-tri
  reference mesh. The mesh is presentation-only; it must never become the
  print-clearance or collision authority.
- Treat multiple plates as stable records, not index-only positions, before
  adding add/remove/reorder interactions.

## Android visibility

On a fresh install, the owner’s visual-review build opens the supplied A1 Mini
3D study once so the reference scene is immediately discoverable. Ordinary
builds open the object-first Alloy-owned model study because they intentionally
omit the unlicensed reference asset. Later launches return to the active
project workspace; the `3D` header action reopens the model study and the `A1`
header action reopens the machine study.
The Hero footer also exposes an `A1 study` action, and the standalone machine
study exposes `Import supplied 3MF`, so the reviewed machine scene and the
user-supplied source can both be reached directly from the phone rather than
depending on a hidden debug shortcut. The standalone study opens in the light,
airy treatment by default to match the supplied product-reference direction;
the in-stage appearance control still switches to the dark treatment.
The Model Atlas also exposes live previews for every bundled, checksum-verified
example. The exact supplied A1 mesh remains available in debug visual-review
builds. For the owner’s private visual-review release, pass
`-PalloyIncludeSuppliedReferenceVisuals=true`; ordinary release APKs continue
to use the Alloy-owned presentation study model until redistribution rights
are recorded.

## Safety constraints carried forward

The reference's published machine volume is useful for presentation, but its
clearance envelope is explicitly marked as a placeholder. Alloy must source
collision limits from a reviewed printer profile before using them to authorize
a print. Bounding boxes for imported models must be computed in world space;
real STL origins are not assumed to be centered.

Slicing must move off the UI thread for real models and real layer heights. The
reference's synchronous demo slicer is not a production engine and is not a
replacement for the validated native SliceBeam path.

## Asset and licensing note

The handoff says the embedded A1 mini geometry came from a user-supplied 3MF
whose `License` metadata is empty. It also says it is not Bambu's proprietary
CAD. Alloy must still obtain explicit redistribution rights or replace the
asset with a clearly licensed model before shipping it in a public build.
