# Alloy v1 implementation note

## Included

The app module keeps its product surface small and auditable. `MainActivity` owns the compact task flow, bundled model library and scrollable typed recipe editor, `MeshModel` reads STL/OBJ/3MF with millimeter unit normalization and bounded decompression, while native-enabled builds tessellate STEP/STP through OCCT before that mesh boundary. `ViewportView` hosts the Alloy-owned Stage 2 GLES surface, `Slicer` creates offline toolpaths, and `GcodePackageWriter` emits a portable inspectable archive. `BatchSliceJobController` now slices populated plates sequentially and stages each result, while `BatchArtifactArchive` validates and packages those independent artifacts without turning them into one unverified printer transaction. `ProjectArchive` provides a separate `.alloy.zip` project container for backing up and reopening source models, plate transforms, the recipe, workshop inventory state and bounded modeling undo/redo timelines on another phone or document provider. Its bounded cache cleanup treats symbolic links as opaque and preserves their containing project, so pruning cannot recursively follow a link into unrelated storage.

Bundled examples live under `app/src/main/assets/models/` and are checked in CI for finite coordinates, non-zero dimensions and watertight topology by `ci/validate_model_assets.py`. User-supplied STL/OBJ/3MF/STEP files remain the supported path for licensed third-party designs. The phone shell supports transformed multi-part 3MF assembly viewing, named OBJ object/group parts, bounded disconnected-solid detection for small/medium STL assemblies, OBJ `usemtl` group preservation as presentation parts without following external MTL/image paths, a visual Parts focus mode, persisted global scale/X/Y tilt/Z-rotation, persisted per-part scale/tilt/Z-rotation/X/Y transforms with bed placement, deterministic clearance-aware 0/90° XY auto-packing, bounded axis-aligned auto-orientation that chooses lower print height with footprint stability tie-breaking, and up to eight independent local plate snapshots. File-provider imports run off the UI thread with cancellation and stale-result suppression. The modeling workbench adds bounded primitives, convex sketch extrusion, a durable per-plate undo/redo snapshot timeline and, in the optional native build, exact OCCT union/subtract/intersect editing with watertight input and result validation. After slicing, the viewport can switch to a top-down, layer-specific toolpath view with distinct perimeter/support colors. A bounded project archive embeds imported source files, state, the reorder/service state of the workshop inventory and validated modeling history snapshots; richer feature-tree CAD history, arbitrary support-aware orientation, and packing optimization remain deferred. Multi-plate artifact export is available as a validated convenience archive, while direct multi-plate printer transactions remain deferred.

## Safety boundary

The on-device fallback slicer is a conservative personal-use implementation. It is useful for simple single-material models, but it is not equivalent to OrcaSlicer or Bambu Studio. It provides bounded grid supports for simple downward-facing overhangs, while the reversible geometry-repair pass removes degenerate/duplicate facets, normalizes closed-component winding, and closes only bounded planar convex openings on single-part meshes; ambiguous, non-planar, non-manifold and multi-part boundaries remain visible and are not guessed. Full multi-object arrangement, modifier meshes, and verified A1 Mini machine-start metadata remain open. The packaged A1 Mini/PLA recipe is now pinned to an upstream profile snapshot for scalar temperatures, speeds, shell/support values and extrusion/cooling limits; the release verifier checks 26 typed projections, 123 source-backed native scalar projections and 11 provenance blobs. Persisted native profile settings are restricted to those 123 source-verified projection keys plus explicitly scoped parity experiments; unknown keys fail closed before they can reach the native config. The static adapter audit now recognizes additional direct arc-fitting, ironing-flow, vase-mode, support interface, support-speed, build-plate-only, infill-overlap, extrusion-width, Z-lift, minimum-retraction-travel and organic-tree equivalents, but the profile remains unverified until native runtime and G4 parity pass. Fallback support output is explicitly marked conservative and unverified; the native engine remains required for production support behavior. Alloy v1 exposes a physical Print action only after the native, profile, support, artifact, pairing, model, certificate and recovery gates pass; production promotion and physical A1 Mini acceptance remain separate gates.

Before printing, inspect the exported archive in a known-good desktop slicer and run a low-risk test only after checking bed limits, temperatures, extrusion mode, and first-layer behavior. Recipe edits are persisted with bounded recovery defaults, and the fallback applies its volumetric speed cap and first-layer temperature transition; neither changes the native/profile/hardware approval boundary. Single-plate and batch foreground requests preserve a deterministic identity over the typed recipe and bounded native profile projection, so a changed recipe cannot silently reach the service after Activity handoff. Project archives fail closed on unsafe ZIP paths, compressed-stream exhaustion, duplicate records, oversized model data, invalid transforms or out-of-range recipe values. Archive format v3 binds every embedded model to its byte count and SHA-256 digest and includes bounded per-plate modeling history snapshots plus their cursor; formats v1 and v2 remain readable for backwards compatibility. They preserve source geometry, inventory state and a bounded PNG workspace thumbnail; the app also keeps a bounded local list of recent portable archives and reference-aware cleanup of extracted source folders.

The export path now performs structural preflight for real, comment-aware G-code mode/shutdown commands, printable extrusion motion, non-empty layers and finite in-bed toolpath coordinates. The same bounded scanner is reused while validating the packaged G-code stream, so large files are not reassembled just to inspect them. When a rendered phone preview is available, the package also carries bounded `Metadata/plate_1.png`, `Metadata/plate_1_small.png` and `Metadata/bbl_thumbnail.png` entries, Bambu-shaped slice-info/model/project metadata and a checked `Metadata/plate_1.gcode.md5`. ArtifactStore stages the validated package in durable app-private storage, flushes it before returning, retains a bounded history, and can recover it only after package, size and SHA-256 checks; the active plate number is included in the artifact filename; transport artifacts also require a matching source size and well-formed digest before upload. The recovered artifact is held separately from the currently loaded model/slice until the interrupted printer transaction is explicitly reviewed. These are artifact-integrity and interoperability checks, not proof of printer safety or Bambu compatibility.

Single-plate slicing is now submitted as an immutable binary-model/typed-recipe request to `SliceJobService`, an Android `dataSync` foreground service. The request snapshot also carries the bounded scalar native-settings projection, preserving the selected profile across Activity recreation and process handoff. The service persists progress, writes the raw result and metadata atomically, validates and stages the package, and broadcasts only the checkpointed job ID. Activity recreation can reattach to a live job; a real process loss promotes a queued/running request to `RECOVERY_REQUIRED` and never presents it as a completed print. Android 13+ notification permission is requested when the user starts a foreground slice or batch, rather than obscuring the first-run 3D study; declining it does not bypass the durable recovery gates. Multi-plate slicing uses the same boundary through `BatchSliceJobService`: its request materializes all sources offline, records each independently validated plate result before advancing, and only exposes a complete batch after the durable manifest is revalidated.

The phone flow also runs a setup preflight before invoking an engine. It blocks
models outside the selected build volume and invalid recipe values, while
requiring the user to acknowledge mesh-health, profile, support and other
unverified warnings before continuing.

Controlled printer work is now owned by `PrinterJobService`, an Android
foreground service. Upload, start, telemetry monitoring and cancellation are
therefore not tied to the Activity window; the persisted lease allows normal
screen recreation while a real process loss still enters explicit recovery.

Workshop inventory now presents reorder, service-soon (within 14 days), due,
and overdue states from the persisted quantity and maintenance schedule.
Filament is tracked in grams and is consumed only after a paired printer
reports COMPLETED; the job ID makes repeated completion telemetry idempotent.

## Deliberately deferred

1. Validate the opt-in provenance-pinned native adapter with a reproducible ARM64 build and Path B parity fixtures, then make it the release default.
2. Extend the Alloy-owned GLES surface with reviewed printer collision
   geometry, richer object arrangement/orientation tools and foldable/desktop
   input affordances. The current renderer already provides perspective orbit,
   pinch zoom, two-finger pan, part picking, a machine/build-volume envelope,
   out-of-volume shading, top-down toolpath inspection and lifecycle-safe
   thumbnails.
3. Add richer searchable project metadata to the portable project container.
4. Validate the implemented Keystore-backed printer pairing plus FTPS upload/MQTT start boundary against a physical A1 Mini Developer Mode fixture; the Android FTPS path now performs explicit BCJSSE session reuse, but hardware confirmation remains open.
5. Extend Android instrumentation coverage on a physical phone for rotation, lifecycle interruption, large files, and Storage Access Framework behavior. The API-35 emulator acceptance test now covers the ordinary model/slice/artifact/project/inventory path; it does not replace those physical-device checks.
